# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build, test, run

Single solution: `Aether.AI.Platform.slnx` (note: `.slnx`, not `.sln`). .NET 10.

```bash
# Lean is a git submodule — init before first build (shallow, pinned to a fixed commit)
git submodule update --init externals/Lean

dotnet build Aether.AI.Platform.slnx          # build everything
dotnet test  Aether.AI.Platform.slnx          # run all test projects

# Single project build/test (dotnet build/test accept ONLY ONE project in this env)
dotnet test tests/Aether.AI.Harness.Tests/Aether.AI.Harness.Tests.csproj --filter "FullyQualifiedName~Memory"

# Run the sample console (composes all contexts). Without an LLM API key it runs an offline smoke check.
dotnet run --project apps/Aether.AI.Sample.Console

# Run the desktop app (Avalonia; Stockapp tenant with CTP/Quotes/Trading; Qifu tenant with Yushu/CloudDocs)
dotnet run --project apps/Stockapp/Acme.Stockapp.Desktop
dotnet run --project apps/Qifu/Acme.Qifu.Desktop
```

The first build after init is slow (Lean source compiles). Lean's transitive deps emit NU1902/3/4 vulnerability advisories (System.Drawing.Common / WCF / WinHttpHandler) — advisory only, expected.

## Big-picture architecture

A multi-context DDD platform built on **Microsoft Agent Framework** (`Microsoft.Agents.AI`, wrapped by `src/Aether.AI.Harness`). Top-level layout enforces a strict layering:

- `src/` — the **Aether.AI platform** itself, standalone. `Aether.AI.Core` (framework-agnostic domain, zero deps), `Aether.AI.Harness` (AgentFactory/HarnessRuntime/SessionManager/ToolRegistry/SkillRegistry/IChatClientFactory wrapping MEAI), `Aether.AI.Workflows` (WorkflowFactory wrapping MAF Workflows — peer of Harness, does NOT depend on Harness), `Aether.AI.Memory` (IConversationStore abstraction + InMemory impl), `Aether.AI.Memory.Sqlite` (SQLite impl, opt-in), `Aether.AI.Hosting` (`services.AddAetherAI()` DI entry point + DefaultChatClientFactory + ConversationTitleService). Platform source never references `business/` or `ai/`.
- `business/` — **pure DDD bounded contexts**, each `Acme.<Context>.{Domain,Application,Infrastructure}`. AI-free.
- `ai/` — **business AI adapters** bridging Aether and each context. Peers of `business/`, kept separate so business stays AI-free. 7 tool adapters (`Ctp/Quotes/Qifu/Notes/Trading/ApkParser/SystemTools`) + 1 bridge adapter (`Agents`). Not every context has an AI adapter — e.g. Automation has none (its business port `IAgentExecutor` is implemented host-side; see [business-port pattern](#business-domain-port--host-implementation) below).
- `externals/` — third-party engines: `Ctp.Net.Core` (native CTP wrapper) and `Lean` (QuantConnect Lean, git submodule).
- `apps/` — consumers/hosts: `Aether.AI.Sample.Console` (CLI), `Acme.Shell` (UI-agnostic shell VM library), `Desktop/Acme.Desktop.Shared` (Avalonia views + composition root), `Qifu/Acme.Qifu.Desktop` + `Stockapp/Acme.Stockapp.Desktop` (tenant host apps).
- `tests/` — all test projects live here, never interleaved with source.

### DDD layering rules (enforced; verify before changing csprojs)

- **Domain** = pure: zero `ProjectReference`, no SDK/HTTP/SQLite/logging packages, no `Aether.AI.*`. Entities/value-objects/ports only. A Domain may reference another context's Domain (shared kernel) — e.g. 8 contexts reference `Acme.AppAuth.Domain`.
- **Application** → Domain (+ foreign Domain port). Never Infrastructure/AI/externals.
- **Infrastructure** → Domain (+ externals + foreign Domain contract). Never another context's Infrastructure.
- **`business/` must NEVER reference `Aether.AI.*`.**
- Dependency graph is a DAG; no cycles. `Acme.AppAuth.Domain` is the pure source (foundation), `Acme.Trading.Runtime.Lean` the pure sink.

### AI adapter convention (`ai/<Context>/Acme.<Context>.AI`)

Every **tool adapter** is the same shape (mirror `ai/Ctp`):
- csproj: `Aether.AI.Hosting` + the context's **Application** project (never Infrastructure/Domain directly).
- `AddXxxTools(this AetherAIBuilder)` registers tools ONLY — there is **no** `AddXxx(modelId)` agent method. Agents are built dynamically by the host/page from the shared tool pool. `ToolNames[]` + `CreateTool<T>` helper using `AIFunctionFactory.Create`.
- Tool classes live in `Tools/`, namespace `Acme.<Context>.AI.Tools`. Tools call Application contracts, never Domain/Infrastructure.
- `AddXxxTools` registers TOOLS ONLY — the host composition root wires business layers.

The **bridge adapter** `ai/Agents/Acme.Agents.AI` is a different shape:
- References `Aether.AI.Hosting` + `Acme.Notes.Application` (custom agents persisted as Notes) + `Acme.AppAuth.Application` (for `IAppServerHttpClient`, marketplace client).
- `AddCustomAgents(this AetherAIBuilder)` registers `ICustomAgentCatalog` (CRUD over Notes-backed agents via `AgentSourceParser`), `ICustomAgentRunner` (maps `CustomAgentDefinition` → `AgentDefinition` → `HarnessRuntime`), `IAgentMarketplaceService` (cloud agent catalog client).
- `AddCustomWorkflows(this AetherAIBuilder)` registers `ICustomWorkflowCatalog` (CRUD over Notes-backed workflows via `WorkflowSourceParser` — JSON, not YAML) + `ICustomWorkflowRunner` (builds participants via `AgentFactory`, wraps as MAF Handoff workflow via `WorkflowFactory.BuildAsAIAgent`, runs through `HarnessRuntime.RunStreamingAsync(AIAgent,…)` — reuses the same `RunStreamingCoreAsync` extraction loop as agents). Workflow persistence: `WorkflowSourceParser` (JSON content, `NoteNodeType.Workflow`) in `business/Notes/Acme.Notes.Application/AgentSource/`. Fields: name/description/category/entry_agent_id/participants/handoffs/handoff_instructions.
- Custom agent persistence: `AgentSourceParser` (YAML front-matter + Markdown prompt) in `business/Notes/Acme.Notes.Application/AgentSource/`. Fields: name/description/category/tools/skills/memory/max_history/model/top_p/max_output_tokens/response_format/enable_web_search/enable_todo_provider/enable_agent_mode_provider/enable_file_memory/enable_agent_skills/enable_open_telemetry/source/marketplace_id/marketplace_synced_at/display_name. `Serialize(AgentSourceFields)` takes a field object (not positional params); `CustomAgentDefinition.ToSourceFields()` projects to it. Business layer defines its own `AgentMemoryMode`/`AgentResponseFormat` enums (parallel to Core's) — adapter maps them, so `Aether.AI.*` never leaks into Notes.

### Business Domain port → host implementation

When **business logic must trigger agent execution** (or anything AI/platform-specific) but business cannot reference `Aether.AI.*`, define a **port interface in the context's Domain** and implement it **in the host composition root**. This is the canonical pattern — do NOT create an `ai/` adapter just to host a port impl, and do NOT make business depend on AI.

- **Port** in `Acme.<Context>.Domain.Interfaces` (e.g. `IAgentExecutor`). Domain stays pure; the Infrastructure service/scheduler depends on the port, not on AI types.
- **Implementation** lives in an AI-aware host project (`apps/Acme.Shell` or `apps/Desktop/...`), depending on platform/AI types (`ICustomAgentRunner`, `IConversationStore`, …), NEVER on business Infrastructure.
- **Registration** at the composition root (`AddDesktopCommon`): `services.AddSingleton<IPort, HostImpl>()`.
- **Reuse, don't re-route**: the impl should call the *same* runtime path the UI uses, not a parallel one. Canonical example — `ConversationBackedAgentExecutor` (`apps/Acme.Shell`): Automation's scheduler calls `IAgentExecutor.ExecuteAsync`; the impl runs the agent via `ICustomAgentRunner.RunStreamingAsync` and persists the turn to `IConversationStore`, so scheduled runs land in「最近会话」with cross-fire memory — identical to the chat page's flow. Each task owns a stable `ConversationId` (stored on the entity) so fires thread into one conversation.
- The business layer raises completion via a port event (`IAutomationScheduler.TaskCompleted`); the host VM subscribes and refreshes UI (task list + recent conversations) on the dispatcher thread.

Reference: Automation is the working template — `business/Automation/` (Domain port + scheduler) + `apps/Acme.Shell/ConversationBackedAgentExecutor.cs` (host impl) + `AddDesktopCommon` (registration).

### Foundation context

`business/AppAuth/` (`Acme.AppAuth.*`, DI classes named `Platform*Extensions`) is the **foundation**: app-server (ABP) OAuth2 auth + authenticated HTTP (`IAppServerHttpClient` with `TenantHeaderDelegatingHandler` + `BearerTokenDelegatingHandler`) + `ICurrentUser`. Other contexts consume its ports — never the reverse.

### Trading + Lean (the engine-bridge pattern)

The 回测/实盘 page, the business Trading context, and the Lean runtime are **four separated layers** with a one-way dependency. The UI and business layers never reference Lean — swapping the runtime is a DI-only change.

```
Desktop 回测/实盘页  (TradingViewModel + TradingView, apps/Stockapp)   ← runtime-agnostic
        ↓ depends on
Trading.Application  (IBacktestApplicationService / ILiveTradingApplicationService)   ← orchestration, Lean-neutral
        ↓ depends on
Trading.Runtime.Domain  (ports: IBacktestRuntime / ILiveTradingRuntime; BarResolution; LiveTradingRuntimeStatus; MarketDataConnectInput)
        ↑ implemented by
Trading.Runtime.Lean  (LeanBacktestRunner / LeanLiveTradingService / CtpBrokerage / TradingHostAlgorithm)   ← the ONLY project referencing externals/Lean
        ↓ consumes (DI-provided, not self-registered): ICtpSession (Ctp context) + IAnalysisManager (Quotes context)

Trading.Domain  (IStrategy / MarketBar / SignalDirection / BacktestResult / BacktestStatistics / EquityPoint / StrategyRegistry)   ← pure, shared by Application + Lean
```

- **`business/Trading/Acme.Trading.Domain`** — pure: `IStrategy` (`WarmUpBars`/`Initialize`/`EvaluateSignal→SignalDirection`), `MarketBar`, `BacktestResult` (`Statistics`/`EquityCurve`/`Logs`), `StrategyRegistry` (static; `AddTradingRuntimeLean` registers `SmaCross`/`Test`; `GetRegisteredNames()` feeds the UI strategy picker).
- **`business/Trading/Acme.Trading.Application`** — `IBacktestApplicationService.RunAsync(BacktestRunInput)→BacktestResult` and `ILiveTradingApplicationService` (`StartAsync(LiveTradingRunInput)→(bool,string?)`, `StopAsync`, `Status`/`IsRunning`, `StatusChanged`/`LogReceived` events). Thin mappers to the runtime ports. `AddTradingApplication()` registers both.
- **`business/Trading.Runtime/Acme.Trading.Runtime.Domain`** — the runtime **ports** (`IBacktestRuntime`, `ILiveTradingRuntime`) + shared enums/DTOs. No Lean.
- **`business/Trading.Runtime/Acme.Trading.Runtime.Lean`** — the **only** project referencing `externals/Lean`. `LeanBacktestRunner` (full backtest: reads K-line via `IAnalysisManager` → CSV → LEAN engine → `BacktestResult`). `LeanLiveTradingService` (LEAN live engine + `CtpBrokerage`). `AddTradingRuntimeLean()` registers the strategies + both runtime impls; it **consumes** (does not register) `ICtpSession` (from `AddCtpInfrastructure`) and `IAnalysisManager` (from `AddQuotesApplication`).
- **Desktop 回测/实盘页** (`apps/Stockapp/.../ViewModels/TradingViewModel.cs` + `Views/TradingView.axaml`, the `backtest` nav): two tabs (回测 + 实盘). The VM depends on `Trading.Application` + `Trading.Runtime.Domain` enums + `Trading.Domain` only — **never** on `Trading.Runtime.Lean`. Wired via the tenant-specific ContentControl+DataTemplate pattern (Stockapp-only; Qifu has no `backtest` nav).
- **AI** (`ai/Trading/Acme.Trading.AI`): `AddTradingTools()` exposes only `RunBacktest` (no live-trading tool to the agent).

Runtime paths:
- **Backtest**: `TradingViewModel.RunCommand` → `Task.Run(() => _backtest.RunAsync(input))` (blocking, so off the UI thread) → `BacktestResult` (12 string stats + `EquityCurve` + `Logs`). **Data caveat**: K-line comes from `IAnalysisManager` (Quotes context, stock-oriented Sina/East/Baidu providers) — futures symbols may have no data; stocks (e.g. `600000`) work.
- **Live**: `StartLiveCommand` → `_live.StartAsync(LiveTradingRunInput)`; preconditions: `ICtpSession` already logged in (CTP connected via the 期货 page) + a complete `MarketDataConnectInput` (md front, built from `CtpConnectorViewModel`). Subscribe to `StatusChanged`/`LogReceived` (dispatch to UI thread). **P1 = signal-only**: `CtpBrokerage.PlaceOrder` logs the intended order and returns `false` — no real CTP order is placed; the tick→bar→signal chain is live.
- **P2 (real orders, future) — no new dependency, no cycle.** `CtpBrokerage` already injects `ICtpSession` (uses it for md subscribe / account query / `OrderReceived`+`TradeReceived` events). P2 just makes `PlaceOrder` call `_session.OrderInsertAsync(CtpOrderRequest)` (Lean Order → `CtpOrderRequest` mapping) and translates the already-subscribed `OrderReceived`/`TradeReceived` back into Lean Order/Trade events. This reuses the **same `ICtpSession.OrderInsertAsync`** port the 期货 page manual trading uses (`ICtpTradingService.PlaceOrderAsync`) — two consumers, one port. The edge `Trading.Runtime.Lean → Ctp.Domain` already exists; `Ctp.*` never references `Trading.*`, so there is no cycle. `CtpBrokerage` must stay in `Trading.Runtime.Lean` (it subclasses Lean's `Brokerage`); Ctp stays Lean-free.
- **Swapping the runtime** (Lean→other): implement `IBacktestRuntime`/`ILiveTradingRuntime` in a new project and replace the `AddTradingRuntimeLean()` registration. `Trading.Application`, `Trading.Domain`, and the desktop VM are untouched.

### Tenant-specific top-level pages (ContentControl + DataTemplate)

Some nav pages are tenant-specific (Stockapp's 期货 page uses CTP; its 回测/实盘 page uses Trading/Lean; Qifu has neither). The shared shell must not reference tenant/CTP/Trading types. Pattern (same as the Experts 连接器 tab):
- Shared `MainViewModelBase` exposes an `object?` content slot + an `IsXxxPage` flag — `Futures`/`IsFuturesPage => CurrentPage == "ctp"` and `Trading`/`IsTradingPage => CurrentPage == "backtest"`; `IsPlaceholderPage` excludes both.
- Shared `MainWindow.axaml` renders each via `<ContentControl Content="{Binding ...}" IsVisible="{Binding Is...Page}" />`.
- The tenant VM+View live in the **tenant project** (`apps/Stockapp/.../ViewModels` + `Views`); the tenant `App.axaml` registers `<Application.DataTemplates>` mappings (e.g. `CtpViewModel→FuturesView`, `TradingViewModel→TradingView`) and the tenant `MainViewModel` assigns the VM to the slot (`Futures = ctpVm; Trading = tradingVm;`). Qifu leaves them null (no nav entries, flags stay false).
- The tenant VM depends only on Application-layer services (e.g. `ICtpTradingService`, `IBacktestApplicationService`) + the shared connector, never on `externals/Ctp.Net.Core` or `Trading.Runtime.Lean` directly.

### Per-agent model + memory (platform layer)

- **Per-agent ModelId**: `AgentDefinition.ModelId` (opaque string) resolved by `IChatClientFactory.Create(modelId)` → `IChatClient`. Platform default (`DefaultChatClientFactory`): uses `AetherAIOptions.OpenAI` key/endpoint. Desktop override (`DesktopChatClientFactory`): maps ModelId = LlmConfig.Id → builds per-provider client.
- **Memory policy**: `AgentDefinition.Memory` (`Full`/`SlidingWindow`/`Off`) + `MaxHistory`. Enforced at agent build time via `HarnessAgentOptions.ChatHistoryProvider`: Full→null (default InMemory), SlidingWindow→`InMemoryChatHistoryProvider` + `SlidingWindowChatReducer`, Off→`NoMemoryChatHistoryProvider`.
- **Extended agent options**: `AgentDefinition` also carries sampling (`TopP`/`MaxOutputTokens`/`ResponseFormat`), HarnessAgent provider toggles (`EnableWebSearch`/`EnableTodoProvider`/`EnableAgentModeProvider`/`EnableFileMemory`/`EnableAgentSkills`/`EnableOpenTelemetry`), `RequireToolApproval` (per-agent tool-approval master toggle, see [Chat streaming surface](#chat-streaming-surface-reasoning--approval--plan--mode--ask_user)), `ToolApprovals` (per-tool level override `name→"Safe"/"Confirm"/"Dangerous"`), and `Skills` (name list). All mapped in `AgentFactory` (Core enums → MEAI; `ResponseFormat` via a Core `AgentResponseFormat` so MEAI types never leak into Core). Provider toggles default off (lightweight runtime); `EnableFileMemory` only takes effect when `AetherAIOptions.FileMemoryRoot` is set.
- **`AetherAIOptions` paths**: `FileMemoryRoot` (writable root for the file-memory provider; null → silently disabled), `SkillsDirectory`, `PythonExecutable`. Set by the desktop composition root to tenant-data subdirs.
- `HarnessRuntime.Invalidate(agentId)` drops cached agent + definition (on edit).
- **Streaming core reuse**: `HarnessRuntime.RunStreamingCoreAsync` (private static) holds the shared streaming loop. It dispatches every `AIContent` kind in the stream to a `StreamHandlers` callback bundle (Core, framework-agnostic): `OnToken` (answer `TextContent`/`update.Text`), `OnReasoning` (`TextReasoningContent`), `OnToolEvent` (`FunctionCallContent`/`FunctionResultContent` → `ToolStreamEvent`), `OnApprovalRequest` (`ToolApprovalRequestContent`), `OnTodoList` (live `TodoProvider` list after `todos_*`), `OnError` (`ErrorContent`), `OnUsage` (`UsageContent` → token summary). Called by both `RunStreamingAsync(Guid sessionId,…)` (agent path, with AetherSession bookkeeping) and `RunStreamingAsync(AIAgent, FrameworkAgentSession,…)` (workflow path, no bookkeeping). This is how workflows reuse the same display pipeline as agents. See [Chat streaming surface](#chat-streaming-surface-reasoning--approval--plan--mode--ask_user).
- **Workflows** (multi-agent Handoff): `Aether.AI.Workflows` project (peer of Harness, only depends on Core + MAF Workflows NuGet). `WorkflowFactory.BuildAsAIAgent(def, participants, id, name, desc)` → `HandoffWorkflowBuilder` → `.Build()` → `AsAIAgent(InProcessExecution.Default)` → `AIAgent`. The adapter (`CustomWorkflowRunner`) builds participants via `AgentFactory.Create` (same factory as single agents) + maps `CustomAgentDefinition`→`AgentDefinition` via `CustomAgentRunner.ToAgentDefinition` (internal). Chat dispatch: `MainViewModelBase.SelectedWorkflow` (non-null → workflow path; null → agent path), both through the same `RunSegmentedStreamAsync` (run delegate).

### Skills (prompt + Python-script capabilities)

Skills are prompt-based capabilities (Agent Skills spec — same `SKILL.md` format as Claude Code) loaded from a directory and surfaced to the agent via MAF's `AgentSkillsProvider`. **HarnessAgent-only** — `ChatClientAgent` (bare chat) has no skills.

- **Plumbing** (`src/Aether.AI.Harness/Skills/`): `SkillRegistry` (name/description/category/content) + `ISkillRegistryContributor` + `ConfigureSkillRegistry`. Mirrors `ToolRegistry` but for static prompt data (no factory). `LoadFromDirectory(dir)` scans `<dir>/<skill-name>/SKILL.md` (frontmatter `name`/`description`/`category` + Markdown body).
- **Runtime source**: `AgentFactory.ConfigureSkillsProvider` builds an `AgentFileSkillsSource` (MAF) from `AetherAIOptions.SkillsDirectory` — discovers `SKILL.md` + scripts (`.py`/`.sh`/`.js` default) + resources, with a custom `AgentFileSkillScriptRunner` that runs scripts as subprocesses (`python3 <script> <args>`, returns stdout). Per-agent selection via `FilteringAgentSkillsSource` by `AgentDefinition.Skills` (empty = all).
- **Approval disabled by design**: the `AgentSkillsProvider` is built manually and injected via `HarnessAgentOptions.AIContextProviders` (the internal default provider is disabled) with `AgentSkillsProviderOptions.DisableLoadSkillApproval/DisableReadSkillResourceApproval/DisableRunSkillScriptApproval = true`. Chat has no approval UI; without this `run_skill_script` is blocked by MAF's default approval (which `DisableToolAutoApproval` does NOT cover).
- **Skills dir** (desktop): `AetherAIOptions.SkillsDirectory = <tenantDir>/skills`. Drop `<name>/SKILL.md` (+ optional `script.py`) and restart. `SkillRegistry` also scans it to feed the expert-edit skill picker (`ICustomAgentCatalog.GetAvailableSkills`).
- Agent opts in via `EnableAgentSkills` + `Skills` (name list), persisted through the custom-agent pipeline (`AgentSourceFields.Skills`).
- `ToolStreamEvent` (tool call/result, paired by `CallId`) lives in `Aether.AI.Core.Agents` — constructed by `HarnessRuntime` from `FunctionCallContent`/`FunctionResultContent` in the stream. Keep it in Core (app/adapter contracts must depend on Core, not Harness internals).

### Chat streaming surface (reasoning / approval / plan / mode / ask_user)

The chat page adapts to HarnessAgent's **full** streaming output. `RunStreamingCoreAsync` branches on every `AIContent` kind (see `StreamHandlers` above); `MainViewModelBase.RunSegmentedStreamAsync` renders each as a `ChatMessageItem` card. All thread through the **same** `RunSegmentedStreamAsync` cooperative loop, so agent + workflow paths both get them. Transcript is grouped into **`ChatTurnItem`**s (`Messages` is `ObservableCollection<ChatTurnItem>`, not flat) — each turn = user request + its agent items under a left-border container with status (Working/Done/Error/AwaitingApproval) + elapsed. Resume reconstructs turns by grouping on user-role messages.

- **Reasoning cards (💭)**: `update.Text` concatenates **only `TextContent`** — `TextReasoningContent` (model "thinking") is structurally separate and reachable only via `update.Contents`. Surfaced via `OnReasoning`; VM streams into a 💭 card (collapsed + dimmed by default, shows elapsed). `ChatMessageItem.IsReasoningContent` distinguishes `TextReasoningContent` segments (always 💭, never become the answer) from `TextContent` segments (intermediate stay 💭 "thinking"; only the last non-empty one flips to the markdown answer at `FinalizeSegment`). Streaming **answer** renders live markdown (`MarkdownContent`, throttled every ~6 tokens) — not raw markdown source.
- **Tool approval — per-tool levels + per-expert override**: tools carry an `Aether.AI.Harness.Tools.ToolApprovalLevel` (declared by adapters at `ToolRegistry.Register`): `Safe` (read-only, auto-run), `Confirm` (reversible write, pop dialog), `Dangerous` (irreversible/order/delete/shell, pop dialog + red badge). When an agent's `RequireToolApproval` master toggle is on, `AgentFactory` wraps only **non-Safe** tools in `ApprovalRequiredAIFunction` (Safe auto-run). The expert author can **override per-tool** via `AgentDefinition.ToolApprovals` (`name→"Safe"/"Confirm"/"Dangerous"`, persisted as `tool_approvals` JSON in `AgentSourceParser`) — `AgentFactory.ResolveApprovalLevel` uses override > declared. The editor tool picker shows a level ComboBox per tool (default = declared) + red/amber badges. MAF approval is a **cooperative re-invocation loop, NOT a callback**: stream emits `ToolApprovalRequestContent` and ends the turn; host re-invokes `RunStreamingAsync` with a `ChatMessage` holding `request.CreateResponse(approved, reason)` (or `CreateAlwaysApproveToolResponse` for "don't ask again") on the **same** `frameworkSession`. `RunStreamingCoreAsync` stashes the original request (`ConditionalWeakTable<FrameworkAgentSession,…>` by `RequestId`); MAF's `ToolApprovalAgent` middleware (default-on) does binding/queuing/standing-rules. `ToolApprovalDecision` (Core DTO) carries the UI decision (`IApprovalDialogService` → `ApprovalDialogService` + `ApprovalWindow`). VM loop: run → if `OnApprovalRequest` fired, pop dialog → re-run with decision → resumed stream re-emits the approved tool's Call+Result, then the answer. `AutoApprovalRules` can auto-approve/defer but **cannot reject** — reject must go through the loop. If `RequireToolApproval` is off, ALL tools auto-run (levels inert).
- **`ask_user` interactive dialog tool**: a host-registered tool (`AddDesktopCommon`, `AskUserTool.AskAsync(AskUserQuestionInput[] questions)` → `IAskUserDialogService` + `AskUserWindow`: a **multi-question form** — each question a section with option buttons + custom text, one 提交 returns all answers as a JSON array in order; user 取消 returns `[]`). `AskUserQuestionInput{Question,Options}` lives in Acme.Shell (UI-agnostic). `AgentFactory` **auto-includes** `ask_user` in every agent (no per-agent Tools opt-in) and **auto-injects** a system-prompt instruction to use it for confirmations + batch multiple questions in one call (else the agent asks in plain text). It is **hidden from the expert tool picker** (`GetAvailableTools` filters it) — it's always-on infra. Registered as `Safe` → never gated by approval (it IS the interaction UI). Mirrors Claude Code's `AskUserQuestion` (which also takes 1–4 questions per call).
- **Plan UI (📋, reuse `TodoProvider`)**: `EnableTodoProvider` wires MAF's `TodoProvider` (`todos_add`/`todos_complete`/`todos_remove`/`todos_get_*`; items `{Id:int, Title, Description, IsComplete:bool}` — binary, no `in_progress`). After any `todos_*` result, the runtime resolves `agent.GetService<TodoProvider>()` + `GetAllTodosAsync(frameworkSession, ct)` and surfaces the live list via `OnTodoList`. VM renders/updates a 📋 plan card **in the transcript** (pinned to turn top, items[1]); completed items `TextDecorations="Strikethrough"`. `todos_*` calls are **suppressed from the generic tool-card path** (OnToolEvent skips `todos_*`). The plan card is **persisted** (`ToTranscriptMessage`: `kind="plan"` + `todos` JSON; `FromTranscriptMessage` rebuilds) — survives restart. Approval (`ItemType="approval"`) cards are runtime-only (skipped in `PersistTurnAsync`); `ApprovalState` (0/1/2) drives ⏳/✅/❌.
- **AgentMode plan/execute**: `EnableAgentModeProvider` wires MAF's `AgentModeProvider` (default modes `plan`=interactive / `execute`=autonomous; default mode `plan`). Mode is per-session state (`AgentSessionStateBag`). `HarnessRuntime.GetModeAsync/SetModeAsync` (resolve `agent.GetService<AgentModeProvider>()` + framework session); `RunStreamingAsync` takes a `desiredMode` param applied at run start (covers new-session-before-first-run). `ICustomAgentRunner`/`ICustomWorkflowRunner` thread `GetMode/SetMode` + `desiredMode`. Input area has a **plan/execute selector** (`HasModeSupport` = selected agent's `EnableAgentModeProvider`; set in `OnSelectedAgentItemChanged` **before** the `_isInitializing` guard or it won't show on startup). After each turn `RefreshModeAsync` re-reads the actual mode (catches agent self-`set_mode`). A **plan-accept bar** shows only when `HasModeSupport && SelectedMode=="plan" && !IsAgentRunning && lastTurnHasPlanCard` (signal-triggered, not every plan turn); `AcceptPlanCommand` → `SetModeAsync("execute")` + re-run a continuation turn.
- **Tool result rendering by type**: `ChatMessageItem.NormalizeToolResult` normalizes `Output` → `ResultKind` (text/code/table/error/json) + `ResultText` + `IsResultLong`; the tool card expanded section picks a template (text one-line, code monospace+scroll, error red, table/json fallback). Collapsed one-liner = `VerbIcon` (by tool-name keyword) + `ToolName(MainArg)`.
- Core DTOs (`ToolApprovalRequest`/`ToolApprovalDecision`/`TodoItemInfo`/`StreamHandlers`/`ToolApprovalLevel`) live in `Aether.AI.Core.Agents` or `Aether.AI.Harness.Tools` — MEAI types (`ToolApprovalRequestContent` etc.) stay confined to Harness. `TodoItem.Id` is `int` (not string).

### Conversation persistence (ChatGPT-style, with tool calls)

- `IConversationStore` (abstraction in `Aether.AI.Memory`) + `SqliteConversationStore` (impl in `Aether.AI.Memory.Sqlite`, opt-in). Desktop uses `conversations.db` in tenant dir.
- `Conversation` has `AgentId`/`AgentName`/`Title`/`Messages`. `ConversationSummary` for sidebar (no full transcript).
- **Full transcript persisted**: `PersistTurnAsync` saves the segmented transcript (thinking segments + tool steps + answer) as `Message` entries — tool steps use `Role=Tool` + `Metadata={kind:tool,input:json,output:json}`; thinking segments use `Role=Assistant` + `Metadata={kind:reasoning}`; answer is plain `Role=Assistant`. `ResumeConversationAsync` reconstructs `ChatMessageItem` tool steps (with Input/Output) + thinking cards + markdown answer via `FromTranscriptMessage`. SQLite `conversation_message` table has a `metadata TEXT` column (JSON); `EnsureAsync` does try/catch `ALTER TABLE ADD COLUMN` migration for old DBs.
- New chat = lazy create (first send). `ICustomAgentRunner`/`ICustomWorkflowRunner` key runtime sessions by `conversationId` (per-conversation memory isolation). Restart restores display only (agent/workflow context fresh).
- `IConversationTitleService` (Hosting) — LLM auto-generates title from first turn (fire-and-forget, 4-12 chars).
- `IPreferencesStore` (desktop `JsonPreferencesStore`) — persists selected agent, summoned list, LLM selection, sidebar expand state.
- **Cross-VM refresh**: `NotesViewModel.NotesChanged` → `Experts.LoadAsync()` + `Workflows.LoadAsync()` (deleting a note that's an agent/workflow refreshes both lists). `WorkflowsViewModel.WorkflowsChanged` → `Notes.LoadAsync()`. Without this, lists are stale until restart. **AI-tool edits**: `INoteService.NotesChanged` event (fired by `NoteService` on Create/Update/Delete) → `NotesViewModel.RefreshAsync` reloads the tree preserving expand-state + selection — so AI-edited notes appear without restart.

## Non-obvious gotchas

- **ABP auth `scope`**: login MUST send `scope = "Abp alphaagent_chat"` (set in `AddDesktopCommon`). Without it, the token lacks the `Abp` API audience → `401 Bearer error="invalid_token"` on all protected endpoints. Refresh does NOT need scope (refresh token preserves scopes).
- **`TenantHeaderDelegatingHandler`**: registered on `IAppServerHttpClient` ahead of `BearerTokenDelegatingHandler`. Sends `__tenant` header (tenant name from `AppServerOptions.Tenant`). `AppServerOptions` is a **plain singleton** (not `IOptions`), so inject it directly — `IOptions<AppServerOptions>` returns a default empty instance.
- **`IAppServerHttpClient.PostAsync<T>` has `where T : class`** — can't use `Guid?`/`bool`. Use `PostRawAsync` + manual parse for value-type responses.
- **`AgentSourceParser.Serialize`** takes a `CustomAgentDefinition` directly (not positional params, not an `AgentSourceFields` type — that no longer exists). Add a new persisted agent field by: extending `CustomAgentDefinition` (Notes Domain) + a parse case in `ParseFrontMatter` (keys are lowercased + underscore-stripped) + the `Serialize` output line + `CustomAgentRunner.ToAgentDefinition` (→ platform `AgentDefinition`) + `AgentDefinition` itself + `ExpertsViewModel` (2 mappings) + `ExpertItem`/`ExpertEditViewModel`/`ExpertEditView.axaml`. List values reuse `ParseListValue` (flow `[a,b]` or block `- a`); maps persist as JSON single-line (see `tool_approvals`). `RequireToolApproval` + `ToolApprovals` (2026-08) are the worked example.
- **File memory read-only crash**: HarnessAgent's file-memory provider defaults to a relative `agent-file-memory` path → `Read-only file system` when launched from a `.app` (CWD=/). Always set `AetherAIOptions.FileMemoryRoot` to a writable dir (desktop: `<tenantDir>/agent-file-memory`); when null, `AgentFactory` silently disables the provider rather than crash.
- **Skill script approval**: MAF's skill tools (`load_skill`/`read_skill_resource`/`run_skill_script`) require approval by default and `DisableToolAutoApproval` does NOT cover them. `AgentFactory.ConfigureSkillsProvider` builds a custom `AgentSkillsProvider` (via `AIContextProviders`, internal default disabled) with approvals off — if you switch back to `HarnessAgentOptions.AgentSkillsSource` (internal provider), `run_skill_script` will be blocked (chat has no approval UI).
- **`.app` PATH**: GUI-launched `.app` has a restricted PATH; `python3` (skill scripts) / other CLIs may not resolve. Set `AetherAIOptions.PythonExecutable` to an absolute path.
- **Theme is light-only**: `SharedTheme.axaml` has no dark variant (hardcoded `White` in places); both tenant `App.axaml` pin `RequestedThemeVariant="Light"`. Don't assume dark mode.
- **Tool call display**: streaming runs use a segmented transcript (`MainViewModelBase.RunSegmentedStreamAsync`) grouped into `ChatTurnItem`s: a tool call+result are merged into ONE `ChatMessageItem` (`ItemType="tool"`) paired by `ToolStreamEvent.CallId`, interleaved with reasoning segments (`IsReasoning`/`IsReasoningContent`) and the answer. `FunctionResultContent` has no `Name` — `HarnessRuntime` resolves it via `CallId`. Card kinds: `text` (reasoning 💭 / answer markdown), `tool` (🔧/✅, result rendered by `ResultKind` text/code/table/error), `plan` (📋, `todos_*`), `approval` (⏳/✅/❌). Persisted to `IConversationStore`: `text`(reasoning/answer) + `tool` + `plan` (kind=plan + todos JSON); `approval` is runtime-only (skipped in `PersistTurnAsync`). See [Chat streaming surface](#chat-streaming-surface-reasoning--approval--plan--mode--ask_user).
- **MAF approval is cooperative, not a callback**: there is NO `ApprovalCallback`/`OnApprovalRequired` delegate in MAF. `ToolApprovalRequestContent` surfaces in `update.Contents` and the stream **ends for that turn**; the host re-invokes `RunStreamingAsync` with a `ToolApprovalResponseContent` message on the same session to resume. `ToolApprovalAgentOptions.AutoApprovalRules` (`Func<ToolAutoApprovalRuleContext,ValueTask<bool>>`) can auto-approve (true) or defer (false) but **cannot reject** — reject must go through the re-invocation loop. `DisableToolAutoApproval=true` removes the middleware entirely (do NOT set it for the approval UI).
- **Tool approval levels default `Safe`**: `ToolRegistry.Register` defaults to `ToolApprovalLevel.Safe` (auto-run). So a **dangerous tool NOT explicitly marked** `Confirm`/`Dangerous` by its adapter will auto-run even when `RequireToolApproval` is on. Adapters MUST declare write/order/delete/shell tools (SystemTools/Ctp/Notes do; new adapters must too). Experts can override per-tool via `ToolApprovals`. `ask_user` is registered Safe deliberately (it's the interaction UI, never gated) and is **hidden from the expert tool picker** + auto-included by `AgentFactory` (don't add it to an agent's Tools list manually).
- **`update.Text` excludes reasoning**: `AgentResponseUpdate.Text` concatenates only `TextContent`; `TextReasoningContent` (model thinking) is only in `update.Contents`. If you add a streaming branch, enumerate `update.Contents` — don't rely on `.Text` alone or reasoning is silently dropped.
- **Workflow = AIAgent**: `WorkflowFactory.BuildAsAIAgent` wraps a MAF Handoff workflow as an `AIAgent` (via `AsAIAgent` + `InProcessExecution.Default`). The adapter runs it through `HarnessRuntime.RunStreamingAsync(AIAgent,…)` — the same `RunStreamingCoreAsync` extraction loop as single agents. Tool calls from participant agents surface as `FunctionCallContent` in the stream (same `ToolStreamEvent` path). `Aether.AI.Workflows` project does NOT reference Harness (peer layer); the adapter (`ai/Agents`) references both and bridges.
- **Chat dispatch (agent vs workflow)**: `MainViewModelBase.SelectedWorkflow` non-null → workflow run path (`ICustomWorkflowRunner`); null → agent path (`ICustomAgentRunner`). Both through the same `RunSegmentedStreamAsync` (run delegate). `ResumeConversationAsync` detects kind by checking if the conversation's `AgentId` matches a workflow in `Workflows.Workflows`.
- **`WorkflowSourceParser` is JSON** (not YAML like `AgentSourceParser`). Workflow definitions have nested handoff structures; JSON is cleaner. `NoteNodeType.Workflow` notes store `WorkflowSourceFields` JSON in Content.
- **SQLite `metadata` column**: `conversation_message` table has `metadata TEXT` (JSON) for tool step input/output + thinking-segment kind. `EnsureAsync` does try/catch `ALTER TABLE ADD COLUMN metadata` migration (old DBs get the column added; new DBs already have it). `Message.Metadata` is `IReadOnlyDictionary<string,string>?`.
- **Markdown rendering**: `Markdown.Avalonia.Tight 12.0.0-a3` in `Acme.Desktop.Shared`. `SelectableMarkdownViewer` (custom subclass of `MarkdownScrollViewer`) for selectable copy (Ctrl+C/Cmd+C). SharedTheme.axaml has code-block font fallback styles to avoid macOS Consolas crash.
- **Lean backtest finalization quirks**: `RunAsync` saves/restores `Console.Out`/`Console.Error`; `resultHandler.StatisticsResults()` wrapped in try/catch (`.First()`-on-empty on sparse equity curves).
- **`SqliteQuoteRepository.ReadAllAsync`** reads columns by ordinal — freq is ordinal 1, date is ordinal 2. Don't swap.
- **`Securities` naming quirk**: namespace `Acme.Securities.*` (plural), DI methods `AddSecurity*` (singular).
- **CTP native libs**: `externals/Ctp.Net.Core` P/Invokes `libctp_native`; prebuilt `.dylib/.so/.dll` ship as Content. CTP auto-login requires saved config + `AutoLogin` flag.
- **Icons**: sidebar nav items + toggle + chat settings use vector `Path` icons (`apps/Acme.Shell/NavIcons.cs`, Lucide paths, bound via `{x:Static}`) to avoid color-font glyph clipping at high DPI. Some emoji remain (account chip, tool-card 🔧/✅/💭). `SharedTheme.axaml` keeps `MinHeight` on `Button.settings-nav`/`nav-rail`/`top-tab` to prevent clipping. **Note node icons**: `NoteIcons.cs` catalog (56+ icons) — Lucide stroke icons (`IsFill=false`) + Simple Icons fill language logos (`IsFill=true`, e.g. `LangPython`/`LangJavascript`/`LangYaml`). Tree/title/icon-picker render dual `<Path>` (Fill vs Stroke by `IconIsFill`). `IconKeyForSyntax(syntax)` auto-maps syntax→icon key; selecting a syntax auto-sets the node icon (user can override manually).
- **Notes code editor (AvaloniaEdit)**: `Avalonia.AvaloniaEdit 12.0.0` in `Acme.Desktop.Shared`. MUST register `<StyleInclude Source="avares://AvaloniaEdit/Themes/Fluent/AvaloniaEdit.xaml"/>` in both tenant `App.axaml` — without it the `TextEditor` renders but is NOT editable (TextArea template missing). `NotesView.axaml.cs` configures VSCode-style: current-line highlight, gray line numbers, Ctrl+wheel zoom (persisted to `IPreferencesStore` key `notes.editorFontSize`, 8–48), Ctrl+F search (`SearchPanel.Install(CodeEditor)`), VSCode Light+ token colors (runtime remap of built-in `.xshd` `NamedHighlightingColors` via `ApplyVscodeColors`), custom YAML `.xshd` (`LoadYaml` — AvaloniaEdit has no built-in YAML). `TextEditor.Text` is NOT a bindable property — sync via code-behind (`SyncCodeEditor` sets `Text` when `Document` non-null, else `Dispatcher.Post` retry; `TextChanged`→`node.Content`). Markdown nodes show two-pane (editor + `SelectableMarkdownViewer` rendered preview) with `GridSplitter` + eye-toggle for preview-only mode (`IsPreviewOnly` → `PreviewColumn`/`PreviewSpan`/`EditorSpan` layout props).
- **Notes tree state persistence**: expand state (`notes.expandedNodes` = JSON `Guid` list) + editor font size (`notes.editorFontSize`) persisted to `IPreferencesStore`. `NoteNodeVM.AnyExpandChanged` static event → `NotesViewModel` throttled save (`_dispatcher.Post` + `_expandSavePending`). `LoadAsync` restores expand state only if a saved record exists (first run = all expanded). New/delete nodes update the tree in-place (no full `LoadAsync`) to preserve expand state.
- **Note node ordering**: `NoteNode.SortOrder` (SQLite `sort_order` column — was unused, now wired through DTO/Service/VM). Right-click 上移/下移 reorders siblings + persists via `UpdateNoteRequest.SortOrder`. New nodes append to end (`SortOrder = max+1`). `LoadAsync` orders roots by `SortOrder` then `Title`. Old DBs get `ALTER TABLE note_node ADD COLUMN icon` migration (try/catch in `EnsureAsync`; `MigrateAddColumnAsync`).
- **TreeView selected text**: Avalonia's default `TreeViewItem:selected` sets accent background but leaves text default-color → unreadable. `NotesView.axaml` adds `<Style Selector="TreeViewItem:selected"><Setter Property="Foreground" Value="White"/></Style>` (scoped via `/template/ ContentPresenter` to avoid bleeding to child rows).
- **Avalonia 12 `CalendarDatePicker.SelectedDate` is `DateTime?`** (not `DateTimeOffset?`). Bind VM date properties as `DateTime?` or you get `InvalidCastException: Could not convert DateTime to Nullable<DateTimeOffset>`. (The 回测 page ran into this.)
- **`Polyline.Points` must never bind to null** — Avalonia builds the geometry on render even when the parent `IsVisible=false`, throwing `ArgumentNullException`. Initialize the points property to an empty list.
- **Securities auto-sync (Stockapp)**: the desktop never used to call `ISecurityClientSyncService.SyncFromServerAsync()`, so `securities.db` was empty → `GetMainFuturesAsync()` returned nothing. Now `CtpViewModel.InitializeAsync` fire-and-forgets an incremental sync on startup + the 期货页 行情 tab has a「同步证券」button. The server endpoint `api/app/security-client-sync/updates` (AllowAnonymous) returns ~5400 securities incl. ~250 futures.
- **Automation (定时任务)**: scheduler is a process-internal 1-min polling `Timer` — fires **only while the app is open** (no cron/Quartz/backfill). Started fire-and-forget from `MainViewModelBase.InitializeAsync`; `AutomationScheduler.StartAsync` has a double-start guard. Each `AutomationTask` owns a stable `ConversationId` (assigned on create) so all its fires thread into one chat conversation via `ConversationBackedAgentExecutor`. `IAutomationScheduler.TaskCompleted` is subscribed by both `AutomationViewModel` (refresh task cards) and `MainViewModelBase` (refresh 最近会话). The scheduler calls `IAgentExecutor` (business port) — must be registered at the composition root or DI resolution of `IAutomationService`/`IAutomationScheduler` throws.
- When adding a new context/adapter, also add its projects to `Aether.AI.Platform.slnx` (folder + `<Project Path=...>`). Not every context needs an `ai/` adapter — if business only needs to *invoke* AI (not expose tools to the agent), use the [business-port pattern](#business-domain-port--host-implementation) instead and skip the adapter.
